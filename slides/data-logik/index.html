01 Opsamling

Følg data —
og forklar hvert led

Fra formularens felter til serverens validering og den færdige HTML.

Overgang til den allerede planlagte opsamlingsaktivitet. [Sources] - Lokal lektionsside: undervisning/010-race-3-data-logik-arrays-og-objekter-07-09-2026.md [/Sources]
Opsamling på øvelse 2 · 10–15 min.

To og to: forklar koden for hinanden

Åbn jeres løsning. Forklar på skift, og peg på de konkrete steder i server.js og views/index.ejs.

Byt efter halvdelen af tiden. Begge skal forklare.

  1. Hvem er client, og hvem er server?
  2. Hvad sker der i server.js?
  3. Hvordan hænger serveren og index.ejs sammen?
  4. Hvad kan EJS, som en almindelig HTML-fil ikke kan?
  5. Hvad består en request og en response af?
  6. Hvor bliver HTML'en bygget — og hvorfor er det SSR?
Bed de studerende forklare med deres egen kode åben. De skal pege på method, action, name, express.urlencoded(), POST-routen, request.body og response.render(). Stop efter cirka syv minutter, og mind dem om at bytte rolle. [Sources] - Lokal øvelse: opgaver/express-ejs-formhaandtering-svarlogik.md [/Sources]
Find svarene i jeres egen kode

Følg data fra formularen til serveren — og tilbage igen

  1. Hvordan sender formularen name og age til serveren?
  2. Hvilken betydning har method, action og inputfelternes name?
  3. Hvor finder vi de indsendte værdier i request.body?
  4. Hvordan bliver inputtet valideret — og hvad sker der, hvis det er ugyldigt?
  5. Hvordan sender response.render() data tilbage til EJS?
  6. Hvordan bliver arrayet names vist som HTML i browseren?
Dette er de konkrete spørgsmål fra den oprindelige opsamlingsaktivitet. De studerende skal ikke nøjes med at svare abstrakt; de skal pege på attributter, variabler, routes, if/else-logik og EJS-tags i deres egen løsning. [Sources] - Lokal øvelse: opgaver/express-ejs-formhaandtering-svarlogik.md [/Sources]
Client/server · request/response

Browseren spørger — serveren svarer

Client Browser viser siden og indsender formularen

Request →metode · URL · body

← Responsestatus · headers · HTML

Server Express + EJS modtager, validerer og renderer

SSR i øvelse 2EJS bygger HTML'en på serveren. Browseren modtager en færdig side.

CSRBrowserens JavaScript modtager data og bygger eller opdaterer selv HTML'en.

Find beviset i jeres kode: Hvor kan I se, at løsningen bruger SSR?

Lad parrene identificere browseren som client og Node/Express-applikationen som server. Bed dem udpege formens method og action, request.body og response.render(). Svaret på bundspørgsmålet er blandt andet response.render() og EJS-templaten: serveren sender færdig HTML. Ved CSR ville browser-JavaScript typisk hente data og ændre DOM'en.
