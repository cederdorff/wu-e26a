Definition · Memory vs. persistent storage

To steder at gemme data — med meget forskellig levetid

I memory · variabler

Data findes kun, mens Node-processen kører. En almindelig array- eller objekt-variabel forsvinder helt ved en genstart, Ctrl+C, eller et crash.

Persistent storage · fil eller database

Persistens betyder, at data overlever, selvom programmet stopper. En fil på disken og en database er begge former for persistent storage — forskellen er bare hvor og hvordan data gemmes.

I dag bruger vi en JSON-fil — den simpleste form for persistens.

Byg definitionen direkte oven på hook-sliden: messages og answers findes kun i memory, mens processen kører. Persistens er det modsatte af det, de allerede har oplevet virker forkert. [Sources] - Lokal lektionsside: undervisning/014-race-4-persistens-json-og-file-system-11-09-2026.md [/Sources]
I dag og senere i forløbet

Samme idé — to forskellige værktøjer

JSON-fil · i dag

  • Simpel: læs hele filen, ret, skriv hele filen igen
  • Ingen opsætning — bare node:fs/promises
  • Fin til én bruger og et lille datasæt

Database · senere

  • Lavet til mange samtidige læsninger og skrivninger
  • Forespørgsler i stedet for at læse hele filen
  • Samme grundidé: hent aktuel tilstand, gem ændringer igen

Selve idéen — gem data et sted, der ikke forsvinder — er den samme.

Understreg, at JSON-filen ikke er en useriøs løsning, men et bevidst simpelt første skridt. Senere i forløbet erstattes filen med en rigtig database, men mønstret read → modify → write genbruges direkte. [Sources] - Lokal øvelse: opgaver/express-ejs-amabot-persistens.md [/Sources]
04 Hvad er JSON?

Data skrevet
som tekst

JavaScript Object Notation — et tekstformat, der ligner jeres egne objekter og arrays.

JSON introduceres som en genkendelig venn, ikke et nyt sprog: det er den samme struktur, bare skrevet som tekst. [Sources] - Lokal lektionsside: undervisning/014-race-4-persistens-json-og-file-system-11-09-2026.md [/Sources]
JSON ligner JavaScript — men er ikke det samme

Nøgler og strings i dobbelte citationstegn

JavaScript-objekt 
const student = {
  name: "Aisha",
  // et JS-objekt
  education: "Multimediedesign"
};
→
JSON-tekst 
{
  "name": "Aisha",
  "education": "Multimediedesign"
}

JSON tillader ingen funktioner, ingen kommentarer og ingen trailing comma.

Peg konkret på forskellene: nøgler i dobbelte citationstegn, ingen kommentar-linje, og ingen komma efter det sidste felt. Dette er præcis de fejl, der giver JSON.parse()-fejl i øvelserne. [Sources] - Lokal øvelse: opgaver/express-ejs-json-students.md [/Sources]
JSON.stringify() og JSON.parse()

Fra JavaScript-data til tekst — og tilbage igen

JavaScript{ id: 1, name: "Aisha" }
→
JSON.stringify()'{"id":1,"name":"Aisha"}'
→
JSON.parse(){ id: 1, name: "Aisha" }

JSON er sprog-uafhængigt — næsten alle programmeringssprog kan læse og skrive det. Derfor er det webbets de facto-standard.

stringify() omdanner JavaScript-data til JSON-tekst, klar til at skrives i en fil eller sendes over HTTP. parse() gør det modsatte. Begge runder trippen tilbage til den samme datastruktur. [Sources] - MDN: https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Objects/JSON [/Sources]

Import og de to metoder

fs.readFile() og fs.writeFile() er asynchronous

import fs from "node:fs/promises";

const data = await fs.readFile(
  "./data/students.json",
  "utf8"
);
const json = JSON.stringify(
  students,
  null,
  2
);

await fs.writeFile(
  "./data/students.json",
  json
);

Begge metoder returnerer et Promise — derfor async/await, ligesom I kender det.

Peg på "utf8" som nødvendigt, for at readFile returnerer tekst i stedet for en buffer. null og 2 i stringify() giver formateret, læsbar JSON i filen. [Sources] - W3Schools: https://www.w3schools.com/nodejs/nodejs_filesystem.asp [/Sources]

Begge routes er nu async — de venter på filen, før de renderer.

Der er ikke længere en messages-variabel uden for disse to routes. Hver route henter den aktuelle historik i starten og — ved ændringer — gemmer den igen, før response.render() kaldes. [Sources] - Lokal øvelse: opgaver/express-ejs-amabot-persistens.md [/Sources]
To hjælpefunktioner: læs og gem

loadMessages() og saveMessages() er den eneste vej til filen

async function loadMessages() {
  const data = await fs.readFile(
    "./data/messages.json",
    "utf8"
  );
  return JSON.parse(data);
}
async function saveMessages(messages) {
  const json = JSON.stringify(
    messages, null, 2
  );
  await fs.writeFile(
    "./data/messages.json",
    json
  );
}

Ingen af funktionerne gemmer noget i en variabel uden for sig selv.

Disse to funktioner er nøjagtig samme mønster som loadStudents()/saveStudents() fra JSON-øvelsen, bare med et andet filnavn. GET / og POST /ask kalder dem, i stedet for at røre filen direkte. [Sources] - Lokal øvelse: opgaver/express-ejs-amabot-persistens.md [/Sources]
