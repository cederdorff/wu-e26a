01 Client/server

Browseren spørger.
Serveren beslutter.

Kommunikation er ikke magi — det er beskeder med en fast struktur.

Overgang til første faglige del. Lad de studerende nævne clients ud over browsere: mobilapps, Postman, andre servere, IoT-enheder. [Sources] - MDN: https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Introduction [/Sources]
Server-side

Når I klikker, søger eller sender en formular, starter browseren en samtale

kliksøgningformularfetch()
En HTTP-request sendes til en server, når brugeren følger et link, sender en formular eller frontendkoden kalder fetch. Serveren behandler requesten og sender et response. [Sources] - MDN: https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Introduction [/Sources]
Client-server-modellen

To roller — én samtale

ClientBrowserStarter requesten
HTTP requestGET /api/jokes
HTTP response200 OK + JSON
ServerNode.jsBehandler og svarer
En client initierer normalt samtalen. Serveren venter på requests, behandler dem og svarer. Client og server er roller — ikke nødvendigvis bestemte slags computere. [Sources] - MDN HTTP Overview: https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview [/Sources]
Ansvarsfordeling

Frontend viser oplevelsen — backend håndterer regler og data

Client / frontend

  • viser UI
  • indsamler input
  • sender requests
  • viser serverens svar

Server / backend

  • validerer input
  • anvender forretningslogik
  • læser og gemmer data
  • sender responses

Grænsen er en arkitekturbeslutning — ikke en naturlov.

Brug som mental model, ikke absolut facit. Server-side rendering kan fx sende færdig HTML, mens en SPA typisk modtager JSON og bygger UI i browseren. [Sources] - MDN server-side introduction: https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Server-side/First_steps/Introduction [/Sources]

beskedformat

HTTP er en protokol for udveksling af resources mellem client og server. Requests kommer fra clienten; responses er serverens svar. [Sources] - MDN HTTP Overview: https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview [/Sources]

HTMLCSSJavaScriptJSONbilledervideo

03 Node.js

JavaScript uden
for browseren

Node.js er et open source, cross-platform JavaScript runtime environment. Det kører V8-motoren uden for browseren. [Sources] - Node.js introduction: https://nodejs.org/learn [/Sources]
Definition

Node.js er et runtime environment — ikke et framework

JavaScript+V8+Node API’er=programmer uden browser

Det giver JavaScript adgang til fx filer, netværk, processer og serverfunktioner.

Adskil runtime fra library/framework. Node giver miljøet og standardbiblioteket; Express installeres ovenpå som et framework. [Sources] - Node.js introduction: https://nodejs.org/learn [/Sources]
Samme sprog · forskellige miljøer

JavaScript får forskellige superkræfter

BrowserNode.js
document og DOMprocess og operativsystem
events fra UIevents fra netværk og filer
Web APIsNode standardbibliotek
sandbox hos brugerenkører på computer/server
JavaScript-sproget er det samme, men de globale API’er afhænger af miljøet. document findes ikke automatisk i Node. [Sources] - Node.js introduction: https://nodejs.org/learn [/Sources]

Live-code dette i en tom mappe. Vis både filen og terminalen. Fremhæv forskellen på at skrive kode og at starte en proces, der kører koden. [Sources] - Node.js introduction: https://nodejs.org/learn [/Sources]

Asynkron I/O

Hold modellen enkel. JavaScript-koden kører i én proces, mens Node tilbyder asynkrone I/O-primitiver. Undgå formuleringen “Node gør alt parallelt”. [Sources] - Node.js introduction: https://nodejs.org/learn [/Sources]

04 Node HTTP

Byg serveren
uden Express

Først ser vi mekanikken. Bagefter lader vi Express fjerne gentagelserne.

Dette kapitel gør Express’ værdi konkret. Vi starter en server med Nodes indbyggede HTTP-modul. [Sources] - Node.js introduction: https://nodejs.org/learn [/Sources]
En server med Node

createServer giver os request og response

import { createServer } from "node:http";

const server = createServer((request, response) => {
  response.statusCode = 200;
  response.setHeader("Content-Type", "text/plain; charset=utf-8");
  response.end("Hej fra Node.js!");
});

server.listen(3000, () => {
  console.log("Serveren kører på http://localhost:3000");
});
Live-code. Peg på callbacken: den kører for hver request. Request beskriver det indkommende kald; response bruges til at sende svaret. [Sources] - Node.js introduction and HTTP server example: https://nodejs.org/learn [/Sources]
Request-objektet

Hvad bad clienten om?

console.log(request.method);  // "GET"
console.log(request.url);     // "/about"
console.log(request.headers); // { ... }
Hvilken metode?Hvilken URL?Hvilke headers?Er der en body?
I det native HTTP-modul skal vi selv undersøge method og url for at afgøre, hvilken kode der skal køre. [Sources] - Node HTTP API: https://nodejs.org/api/http.html [/Sources]
Response-objektet

Hvordan skal serveren svare?

response.statusCode = 200;
response.setHeader("Content-Type", "application/json");
response.end(JSON.stringify({ message: "Hej" }));
Hvilken status?Hvilken content type?Hvilken body?Hvornår afsluttes svaret?
response.end afslutter svaret. Hvis koden ikke afslutter request-response-cyklussen, bliver browseren ved med at vente. [Sources] - Node HTTP API: https://nodejs.org/api/http.html [/Sources]
Routing — manuelt

Uden framework matcher vi selv metode og URL

if (request.method === "GET" && request.url === "/") {
  response.end("Forside");
} else if (request.method === "GET" && request.url === "/about") {
  response.end("Om AMAbot");
} else {
  response.statusCode = 404;
  response.end("Ikke fundet");
}

Det virker — men bliver hurtigt svært at læse og udvide.

Dette er spændingen, Express løser. Lad dem selv pege på gentagelser og kommende problemer med mange routes og body parsing.

05 Express.js

Mindre plumbing.
Tydeligere routes.

Express lægger routing og middleware oven på Node.js.

Express er et minimalistisk routing- og middleware-framework. Det erstatter ikke Node; det kører oven på Node. [Sources] - Express middleware guide: https://expressjs.com/en/guide/using-middleware/ [/Sources]
Hvorfor Express?

Samme serveridé — mindre gentagelse

Node HTTP
if (request.method === "GET" &&
    request.url === "/about") {
  response.end("Om AMAbot");
}
→
Express
app.get("/about", (req, res) => {
  res.send("Om AMAbot");
});
Express matcher metode og path og kalder den tilhørende handler. Det giver mere deklarativ og læsbar routing. [Sources] - Express routing guide: https://expressjs.com/en/guide/routing/ [/Sources]
Projektsetup

Installér Express som dependency

mkdir hello-express
cd hello-express
npm init -y
npm install express
{
  "type": "module",
  "scripts": {
    "dev": "node --watch index.js"
  }
}

node --watch genstarter processen, når filerne ændres.

Vis package.json efter install. Express står under dependencies. node --watch er indbygget i moderne Node-versioner; de kan også starte med node index.js. [Sources] - Express install guide: https://expressjs.com/en/starter/installing.html - Node CLI: https://nodejs.org/api/cli.html [/Sources]
Hello Express

Fem linjer etablerer serverens grundform

import express from "express";

const app = express();

app.get("/", (req, res) => {
  res.send("Hello Express!");
});

app.listen(3000, () => {
  console.log("Serveren kører på http://localhost:3000");
});
Gennemgå import, app, route og listen. Forklar at callbacken til app.get er en route handler. [Sources] - Express basic routing: https://expressjs.com/en/starter/basic-routing.html [/Sources]
Express request/response

Express gør cyklussen konkret i koden

GET /about→app.get("/about", handler)→res.send("Om AMAbot")
reqdet, clienten sendte
resdet, serveren sender tilbage
Peg på sammenhængen mellem den konkrete HTTP-request og route-definitionen. req og res er Express’ abstraherede request/response-objekter. [Sources] - Express routing guide: https://expressjs.com/en/guide/routing/ [/Sources]
Routing

En route er kombinationen af metode og path

GET+/api/jokes+handler=route
app.get("/api/jokes", (req, res) => {
  res.json(jokes);
});
To routes kan dele path, hvis metoden er forskellig. GET /api/jokes og POST /api/jokes er forskellige routes. [Sources] - Express routing guide: https://expressjs.com/en/guide/routing/ [/Sources]
GET routes

Forskellige URLs kan give forskellige svar

GET /forside
GET /aboutom projektet
GET /api/jokesalle jokes som JSON
app.get("/api/jokes", (req, res) => {
  res.status(200).json([
    { id: 1, text: "404: Joke not found" }
  ]);
});
res.json sætter korrekt JSON-response. Status 200 er standard her, men den eksplicitte status gør intentionen tydelig i undervisningseksemplet. [Sources] - Express routing guide: https://expressjs.com/en/guide/routing/ [/Sources]
Data ind i en route

Path params og query params løser forskellige opgaver

/api/jokes/42req.params.ididentificér en bestemt resource
/api/jokes?limit=5req.query.limitfiltrér eller tilpas resultatet
app.get("/api/jokes/:id", (req, res) => {
  const jokeId = Number(req.params.id);
  // find og returnér den valgte joke
});
Dette er en introduktion, ikke en fuld gennemgang. req.body behandles på næste slide. Parametre kommer ind som tekst og skal ofte konverteres og valideres. [Sources] - Express routing guide: https://expressjs.com/en/guide/routing/ [/Sources]
POST + JSON

Middleware gør request-body tilgængelig som JavaScript

app.use(express.json());

app.post("/api/jokes", (req, res) => {
  const newJoke = {
    id: crypto.randomUUID(),
    text: req.body.text
  };

  res.status(201).json(newJoke);
});

express.json() skal registreres før routes, der bruger req.body.

express.json er built-in middleware. Den parser indkommende JSON og udfylder req.body. Senere skal input valideres; her fokuserer vi på flowet. [Sources] - Express middleware guide: https://expressjs.com/en/guide/using-middleware/ [/Sources]
Middleware

Funktioner i rækkefølge — før det endelige response

request→logging→JSON parsing→route handler→response 
app.use((req, res, next) => {
  console.log(req.method, req.url);
  next();
});

Middleware skal sende et response eller kalde next().

Rækkefølgen betyder noget. En middleware kan køre kode, ændre req/res, afslutte cyklussen eller sende kontrollen videre med next. [Sources] - Express middleware guide: https://expressjs.com/en/guide/using-middleware/ [/Sources]
Statiske filer

Express kan servere HTML, CSS, JavaScript og billeder direkte

app.use(express.static("public"));
public/
├── index.html
├── styles.css
├── app.js
└── images/
    └── logo.svg

public er filesystem-mappen — men er ikke en del af URL’en.

Med public/index.html kan localhost:3000/ vise en rigtig side. Express finder filerne relativt til den angivne static root. [Sources] - Express static files guide: https://expressjs.com/en/5x/starter/static-files/ [/Sources]
Fallback route

Hvis intet matcher, skal serveren stadig svare

app.use((req, res) => {
  res.status(404).json({
    error: "Route not found"
  });
});
Placér den sidstExpress gennemgår middleware og routes i den rækkefølge, de registreres.
app.use uden path matcher alle requests, der når hertil. Derfor skal fallbacken stå efter de rigtige routes. [Sources] - Express middleware guide: https://expressjs.com/en/guide/using-middleware/ [/Sources]
